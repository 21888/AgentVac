# AgentVac

[简体中文](README.md) · [English](README.en.md) · [繁體中文](README.zh-TW.md) · [日本語](README.ja.md)

適用於 Codex、Claude Code、Cline 和 Cursor 的開源桌面清理工具。分析磁碟用量、預覽整理範圍，在 macOS、Windows 和 Linux 上安全隔離或還原本機資料。

**版本狀態：** 四工具支援已納入**尚未發布的 v0.2.0 開發中原始碼**，仍在驗收中。**目前 v0.1.0 下載版僅支援 Codex**，尚未推出多工具發行版。

- **先了解資料**：查看檔案邏輯大小、分類、整理候選項目與保護原因。
- **操作前先預覽**：選擇工具與資料目錄，核對個別檔案或完整整理單元。
- **保留還原途徑**：本機隔離、依批次記錄，還原時不覆寫既有資料。
- **舒適使用**：淺色、深色與跟隨系統佈景主題；提供 Codex SQLite 與日誌的唯讀診斷。

本文件提供四種語言；**應用程式介面目前僅支援簡體中文**。AgentVac 是獨立專案，並非所支援工具廠商的官方產品。

| **Claude Code** | 標準舊除錯日誌；可選的本機工作階段封存，包含主記錄及所有已識別的關聯檔案                                             | 最新及使用中的工作階段、全域提示歷史、記憶、憑證與未知配置；不清理 Desktop、Cowork 或雲端歷史         |

只有明確支援的路徑與完整已識別配置才可能成為候選項目，仍需通過時間、活動狀態、檔案系統與處理程序檢查。找到目錄不代表其中所有資料都能清理。Claude Code 工作階段封存後需還原才能繼續，全域提示歷史保持不變。Cline 重建快取時，搜尋或離線模型清單可能暫時無法使用。Cursor 下次啟動可能重新下載資源或編譯快取；還原不會覆寫已重新產生的資料。

詳細範圍見 [Claude Code](docs/CLAUDE-CODE-SCOPE.md)、[Cline](docs/CLINE-SCOPE.md)、[Cursor](docs/CURSOR-SCOPE.md)、[完整整理單元與還原](docs/SAFE-CLEANUP-UNITS.md)及[驗收矩陣](docs/MULTI-AGENT-ACCEPTANCE.md)。合成資料測試不代表相容於每個已安裝的工具版本，也不代表最終跨平台發行驗收完成。

## 對話管理（開發中）

開發原始碼可在另行授權後，於本機讀取四種工具已支援的對話格式，依標題、專案、正文關鍵字與原始對話時間篩選，並分頁顯示長訊息。已驗證的 Claude Code 完整工作階段組可進入隔離預覽；Codex、Cline、Cursor 的正式歷史寫入仍受限制，唯讀瀏覽不等於完整封存支援。

Cursor 資料庫讀取會建立私有本機暫存副本，可能包含未查詢的設定或驗證頁；預設累計預算為 512 MiB。Windows 必須通過實際唯讀 ACL 權限檢查，跨平台原生驗收仍在進行。Cline SDK 目錄與 Cursor agent-transcripts 可獨立選為唯讀來源。[範圍、隱私與限制](docs/CONVERSATION-MANAGEMENT.md)。

**v0.1.0 安全提醒：** 建議只整理舊日誌，不啟用工作階段檔案隔離。目前 Codex 分頁歷史可能參照其他記錄；新版原始碼已停止新的工作階段隔離，既有已簽署記錄仍可還原。

**目前 macOS 尚未完成 Developer ID 簽章與 Apple 公證，Windows 尚未完成 Authenticode 簽章。** Gatekeeper 或 SmartScreen 可能顯示警告或阻止啟動。請勿停用系統防護、Chromium sandbox 或 AppArmor 來略過警告。建置成功或壓縮檔完整，不代表一般首次啟動的系統信任驗證已完成；建議先使用示範資料。

## 第一次使用

以下保留目前介面的簡體中文按鈕名稱，並附上繁體中文說明。

1. **先試用示範。** 點選「体验演示扫描」（體驗示範掃描），在獨立 Codex 示範工作區練習預覽、隔離與還原。示範工作區會保留上次的操作狀態。
2. **選擇工具與資料目錄。** 開發版先在頂端選擇 Codex、Claude Code、Cline 或 Cursor，再使用原生資料夾對話框連接目錄。v0.1.0 僅支援 Codex，通常是 `~/.codex` 或 `CODEX_HOME` 指定位置。請選擇對應工具的資料根目錄，不要選擇專案目錄或磁碟根目錄；Cursor IDE 的資料目錄與 `.cursor` 不同。建議位置僅供參考，不會自動掃描。
3. **備份檔案與還原金鑰。** 先備份資料，再到「目录与恢复」（目錄與還原）選擇「导出恢复备份」（匯出還原備份）。備份含有敏感金鑰資料，應離線妥善保管，請勿上傳或分享；金鑰不能取代檔案備份。
4. **掃描並檢查預覽。** 預設保護最近 **30 天**的檔案。先選少量符合條件的舊日誌，查看保護原因、掃描完整性，以及所選工作階段或快取單元的所有成員。操作真實資料前，請結束對應工具及所有相關 CLI、桌面、IDE、SDK 與背景處理程序，並在應用程式中確認；處理程序仍在執行或狀態不明時會阻止操作。
5. **嘗試還原。** 在「隔离记录」（隔離紀錄）還原剛才的批次。既有檔案與目錄不會被覆寫或合併；若有衝突、資料變更或上層目錄遺失，相關項目會保留，處理後可在對應工具仍關閉的情況下重試。
6. **最後才考慮垃圾桶。** 確認批次不再需要後，才移至系統垃圾桶（Windows 為資源回收筒）。系統 API 失敗時會保留檔案，不改用永久刪除。

若 Codex SQLite 或日誌位於其他目錄，可在「空间诊断」（空間診斷）主動新增位置、勾選範圍，再執行「只读统计」（唯讀統計）。設定中的路徑提示只有在主動啟用設定讀取後才會解析，也不會自動存取。其他工具依上述各自範圍進行中繼資料掃描。

## 安全與保護範圍

**隔離不等於釋放磁碟空間。** 檔案會先移入所選目錄內的 `.agentvac-quarantine`；移至系統垃圾桶後通常仍占用磁碟。只有使用者在作業系統中清空垃圾桶後，才可能釋放空間，清空後無法還原。AgentVac 不提供永久刪除功能。

- **明確的候選範圍**：Codex 舊輪替日誌仍可整理；新的工作階段檔案隔離已停用，既有已簽署記錄仍可還原。已支援的 Claude Code 完整工作階段群組仍需主動複核，還原後才能繼續。
- **關鍵資料保持保護**：憑證、設定、主資料庫及附屬檔案、專案資料與未知配置。唯一明確的資料庫快取例外是 Cline 已識別的衍生搜尋快取及關聯檔案，作為不解析內容的完整單元移動，不執行 SQL。
- **完整單元不可拆分**：已支援的工作階段群組與快取目錄不能逐一選取內部檔案。成員未知、掃描不完整或配置改變時會保護整組；每個單元最多 5,000 個節點、12 層子目錄。
- **不跟隨連結**：符號連結、多重硬連結、特殊檔案、跨磁碟區單元成員與保護天數內的檔案皆不可隔離。
- **保守執行**：預覽僅在短時間內有效、只能使用一次，執行前會重新驗證；相關處理程序必須保持關閉，檢查失敗或狀態不明時會阻止操作。不執行 SQL 清理、VACUUM、checkpoint 或資料庫模式轉換；Codex 日誌資料庫的深入唯讀檢查另有嚴格前置條件。

掃描預設最多存取 **50,000 個項目**，可改為 100,000；項目數包含目錄，另有深度 12 與結果預算 24 MiB 的限制。不完整掃描會明確標示並停用批次選取。每批最多 5,000 項。圖表與小計僅表示已找到的一般檔案之邏輯大小，不能視為整個目錄占用或可釋放量。

還原時也會核對檔案快照。清單通過金鑰驗證，不代表已逐位元組比較或以雜湊驗證檔案內容。跨磁碟區複製、更換電腦或從系統垃圾桶還原，可能改變檔案識別資訊，導致自動還原被拒絕；請保留完整批次與原始金鑰備份，不要手動修改清單來略過檢查。要從系統垃圾桶還原，請先透過作業系統將整個批次資料夾放回原 `.agentvac-quarantine/<批次ID>`，再由 AgentVac 驗證並還原至原位置。

完整目錄還原不保證保留所有平台特有的 ACL、延伸屬性或建立時間。多成員檔案群組使用持久還原紀錄，不等同於一次不可分割的檔案系統重新命名。

## 隱私與執行限制

一般掃描只讀取檔案中繼資料，不讀取日誌或工作階段內容，也不上傳使用者檔案。主動啟用的設定路徑解析、唯讀資料庫結構與頁面狀態檢查，以及應用程式本身的還原金鑰與清單讀取，皆為獨立且受限的流程。AgentVac 不啟動或升級這些工具。

Renderer 沒有 Node 權限，並啟用 sandbox、context isolation 與 CSP。預覽僅在短時間內有效、只能使用一次，執行前會重新驗證；隔離使用同磁碟區移動，還原不覆寫既有檔案。

請勿以提升權限的方式執行、在不可信任使用者可寫入的目錄使用，或在對應工具或其背景服務執行時整理資料。重複路徑檢查無法排除所有惡意競態，也無法保證突然斷電或磁碟故障時的資料一致性。重要資料仍需獨立備份。

## 從原始碼執行與建置

使用 Electron、Vue 3 與 TypeScript。需要 Node.js `^22.17.0` 或 `>=24.0.0` 及正常桌面工作階段；目前 `package-lock.json` 鎖定 Electron `44.5.1`，請使用 `npm ci` 安裝鎖定版本的相依套件。

```sh
npm ci
npm run dev

# 正式環境建置後啟動
npm run build
npm start
```

檢查命令：

```sh
npm test
npm run typecheck
npm run build
npm run test:e2e
npm run test:app-data
npm run test:ux
npm run test:bulk
npm run test:scan
npm run test:accessibility
npm run test:desktop
npm run test:providers
```

桌面檢查需要目標作業系統的 GUI 與原生服務。測試使用產生的測試資料，不掃描使用者的真實資料；瀏覽器或輔助處理程序測試不能取代最終發行檔案的原生驗證。

```sh
npm run dist:mac    # macOS arm64 / x64：DMG、ZIP 建置目標
npm run dist:win    # Windows x64：NSIS、portable EXE 建置目標
npm run dist:linux  # Linux x64：僅 tar.gz
npm run pack       # 目前平台尚未封裝成壓縮檔的應用程式目錄
```

以上為建置目標，實際發行檔案請以下載區為準。GitHub Actions 原生驗證通常依需求手動執行；特定原始碼驗收可能使用暫時的觸發條件，請以目前工作流程檔案為準。驗證不會自動發布 Release。

`SOURCE-SHA256.json` 記錄已發布原始碼快照內各檔案的雜湊，包含程式碼、測試、文件與截圖，不用於驗證發行應用程式。下載應用程式請使用對應發行版的 `SHA256SUMS.txt`。
