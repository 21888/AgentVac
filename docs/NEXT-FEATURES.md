# 新增功能使用说明

适用于 `AgentVac-next` 验证版。本文描述已实现的扫描覆盖、只读空间诊断、目录/恢复钥匙管理与持久演示；**不包含日志数据库的生产压缩或删除**。包版本号仍为 `0.1.0`，不能据此推断已正式发布。

## 安装后先确认两件事

1. 选与你的系统/处理器对应的构建，核实来源与校验和。当前签名、公证与三平台新版本原生验收未完成；系统阻止运行时，不要关闭安全防护绕过。
2. 先用合成演示完成一次「扫描 → 预览 → 隔离 → 恢复」。Linux 还需正常桌面、AppImage 所需运行环境，以及可工作的系统回收站工具/后端。缺少这些条件时，不能把源码构建成功当作安装成功。

安装、开发启动与打包命令见 [README](../README.md)。

## 定位实际 Codex 数据

### 先明确目录用途

- **Codex 数据目录**：用于「空间分析」和隔离/恢复。默认建议为主目录下的 `.codex`；`CODEX_HOME` 可指向其他位置。
- **独立 SQLite 目录**：用于只读空间诊断；可能由 `CODEX_SQLITE_HOME` 或 Codex 的 `sqlite_home` 配置指向。
- **普通日志目录**：用于只读空间诊断；可能来自 `log_dir` 配置。

同一个 Codex 客户端可能把会话、数据库和普通日志放在不同位置。默认路径或环境变量只是候选，不是存在、可读、当前使用中或可清理的证明。应用不自动探查主目录，不全盘寻找旧目录，也不跟随配置提示递归发现更多位置。

### 实际操作

1. 打开「目录与恢复」，检查「未验证」建议，或用「选择真实目录」打开原生文件夹对话框，选择确定属于自己的数据根目录。
2. 连接后不会自动扫描真实文件。回到「空间分析」主动开始扫描。
3. 如果数据库/日志位于别处，进入「空间诊断」明确添加对应目录，再勾选要统计的位置。独立诊断目录不会悄悄切换当前隔离/恢复根目录。
4. 需要参考配置时，主动勾选「允许只读解析所选 Codex 目录的路径配置」。只从大小受限的 `config.toml` 中提取支持写法的顶层 `sqlite_home` / `log_dir` 路径；不输出配置正文、凭据、profile 内容，也不实现完整 TOML/配置继承解析。不支持的写法请手动选择。
5. 新发现的配置路径仍为「未验证」。只有你点击添加并再次明确选择诊断范围，才会访问其目录。

最近记录最多 12 条，按使用顺序保留。启动可通过目录元数据重新打开最近的 Codex 选择，但不自动扫描；缺失、磁盘离线、同路径换成另一目录时明确提示，不定位替代目录。移除最近记录只移除记录，不删除磁盘文件。记录损坏或写入冲突时停止对应保存操作，保留原记录与安全的当前选择。

## 扫描覆盖与选择

- 默认最多访问 **50,000 项**，可主动选择 **100,000 项**，目录也计入访问数。
- 可显示结果另受 **24 MiB** 序列化预算限制；最大递归深度为 **12**。修改访问上限不会取消预算、深度或保护规则。
- 进度区显示已访问项、发现文件/逻辑大小等。取消不会修改源文件；取消后重新扫描，旧预览不能继续操作。
- 达访问量/结果预算、存在不可访问条目或达到递归深度限制时，结果标为 `partial`。表头与跨页等批量选择停用；可以逐项选择已经发现且符合规则的文件，预览再次提示覆盖不完整。
- 「完整」仅表示本次允许遍历范围未触发这些中断条件。受保护和未知目录本来就不展开，不能推断整个 Codex 根目录已全部检查。
- 图表、候选与小计是**已发现文件的逻辑大小**。稀疏文件、未展开目录、文件系统分配粒度等会导致它与实际磁盘占用不同。

完整扫描下，跨页选择按当前分类、搜索与时间筛选生效，并替换旧选择；每批最多 5,000 项，超出会拒绝而不是静默截断。会话需主动开启复核和风险确认。无论结果是否完整，当前日志、缓存、配置、凭据、history、索引、SQLite/状态库、未知项目及不安全链接均不可借批量选择绕过保护。

## 只读诊断与深入检查

### 普通统计

一次最多选择 8 个已保存且仍可用的位置。统计有界，不递归用户会话或项目，也不因为路径提示就自动加范围。可分别查看：

- 数据库主体的逻辑大小
- WAL、SHM、Journal 旁路文件的大小
- 普通日志大小
- 可取得时的分配字节，以及所在磁盘可用/总空间采样

「SQLite 相关文件」合计包括数据库主体及其旁路文件，**也包含受保护的状态库**；它不等于日志库总量或允许清理的字节数。普通日志另列，不混入这个合计。诊断文件条数和目录枚举有上限，出现警告时只代表已经观察到的部分；空结果不能证明目录为空。

磁盘采样受其他进程、系统缓存和后台写入影响，不等于本次操作节省的空间。同一卷可能按多个位置重复采样，不能直接相加。移动到同卷隔离区不释放空间，移动到系统回收站通常也不释放；由用户在系统中清空后才可能回收，仍不承诺与应用逻辑大小完全相同。

### 深查的全部前提

仅支持已选 Codex/SQLite 位置直接包含的 **`logs_2.sqlite`**，且库内结构需匹配已识别的 Codex 日志 v2 表/索引结构。不是按文件名就认定任何数据库安全。

1. 先完成统计并选择该数据库。
2. 主动允许只读结构/页信息检查。
3. 退出所有使用这些位置的 Codex CLI、桌面进程，并勾选确认。
4. 检查前、检查后的进程检测都必须返回 `clear`。`running`、`unknown` 或检测失败均阻断；人工勾选不能代替检测。
5. 不能存在 `-wal`、`-shm` 或 `-journal`，即使旁路文件为空也会拒绝。**不要为了让检查通过手动删除这些文件。**
6. 路径不得含链接，源文件及旁路状态在检查期间必须稳定；不支持的 schema、文件变化或 immutable 打开不受支持时停止，不提供页指标。

只有独立解析进程载入 SQLite，以只读、`immutable=1` 模式读取有限结构信息和 PRAGMA；不读取日志表的用户记录，不执行数据库写入、恢复 WAL、VACUUM、checkpoint 或模式转换。解析前后比较文件身份、大小、时间与旁路状态；这些是稳定元数据观察，**不是全文件哈希，也不能证明稍后不会出现新的写入者**。

深查有独立监督进程，默认时限 **5 秒**。点击「取消诊断」可停止本次检查；正常退出应用会取消并收尾所属辅助进程，监督器也处理父进程断开/心跳中断。超时、取消、辅助进程失败或协议异常均丢弃页指标，不回退到主进程中的同步 SQLite 检查。系统调度和进程清理可能使实际结束时间略长于设定时限；跨平台生命周期行为仍需要原生验收。

成功时显示 `page_size`、`page_count`、`freelist_count`、空闲/非空闲页逻辑大小、`auto_vacuum` 与 `journal_mode`。**空闲页不等于可立即释放的空间。** 本版不替你更新 Codex，也不转换旧数据库维护模式；是否更新客户端请按其官方流程处理，再退出全部客户端后重新观察。

## 钥匙备份与恢复流程

### 操作之前主动导出

在「目录与恢复 → 恢复密钥」确认安全保管，点击「导出恢复备份」，选一个新文件；不会覆盖既有目标。导出 JSON 含敏感 HMAC 材料，界面只显示公开 ID，不展示密钥内容。不要将备份传给别人、提交代码仓库或用于普通问题反馈。应用不代管云端备份。

同时备份数据与整个隔离批次。钥匙能验证清单，不能找回已经丢失的 `.data` 文件。

### 重装、缺钥匙或迁移后

1. 选择实际仍保存 `.agentvac-quarantine` 的 Codex 根目录，不手工修改签名清单中的路径。
2. 用「只读核实隔离区 → 读取留存情况」查看留存文件数、逻辑大小和认证状态。没有匹配钥匙时仍可看到受限的留存信息；达到上限会说明不完整。
3. 只导入自己的原恢复备份。支持本版版本化备份及旧版 32 字节原始 `.key`；导入按公开 ID 合并、重复导入不重复计数，可信集合最多 16 把。格式异常或保存冲突时拒绝，保留已有材料。
4. 导入后重新检查记录。旧扫描、选择与预览被清空，防止继续使用导入前状态。导入成功不等于批次认证成功；若当前目录同时移走，导入结果仍会说明已成功保存钥匙，并要求重新选目录。
5. 清单认证通过后，再在「隔离记录」核对批次并恢复。仍需关闭相关 Codex 进程并通过文件/目标校验；已有目标绝不覆盖，失败项保留。

主钥匙不能安全使用时，新隔离和批次移入 Trash 都被阻止，但不删除已有隔离数据。若保留了可信原钥匙，符合其他校验条件的旧批次仍可恢复。原主钥匙遗失或被替换后，新生成的钥匙只能对应新记录；旧批次需要原钥匙，不能把缺钥匙误判为文件已损坏。

### 「已认证」究竟保证什么

- HMAC 认证针对**恢复清单**；只读救援界面的文件数量/大小来自元数据检查。
- 清单已认证不等于 `.data` 的正文经过逐字或哈希验证，更不等于可以忽略改动。正常恢复/批次 Trash 会进一步核对保存的身份、大小、时间等快照。
- 导入钥匙不会自动重定位原根目录，也不会绕过文件身份要求。跨设备/跨卷复制或操作系统回收站还原可能改变身份，即使钥匙正确也可能阻止自动恢复。
- 系统回收站中的批次需要先整体还原到原隔离位置，再由应用尝试恢复原路径。不要只拿出某个 `.data`，不要修改清单；无法验证时保留原物与备份，先检查原因。

## 持久演示与重置

演示只创建在本份应用配置的 **`userData/demo-workspace`**。首次生成后，重复载入/重启不会重新铺文件，也不会补回已隔离、恢复或由用户修改的内容。演示稀疏文件的逻辑大小不代表实际分配字节。

应用以可信钥匙签名的归属标记确认唯一路径及目录 device/inode，并记录 `preparing` / `ready` 阶段。目录链接、非本应用归属或未知目录、复制到替代目录的标记或不可信签名不会被当作自己的演示覆盖。

「重置演示目录」会再次确认，并依次：

1. 认证演示归属；主钥匙和系统 Trash 适配器必须可用。
2. 有界清点模板路径和应用隔离记录；未知新增文件/目录、符号/硬链接、不能认证的记录或未列入清单的 `.data` 阻断。不会打开未知普通文件的正文。请先由用户移出或另存额外资料。
3. 对中断遗留的精确命名完成标记，只有签名与目录身份有效才认作应用生成内容；不泛放行 `.tmp`。
4. 将**整份旧演示工作区**移入系统回收站，确认原位置已消失后才创建新演示；无删除或改名替代系统 Trash 的降级方案。

重置包含已知模板文件上的修改，以及经名单认证的隔离内容；名单认证不是数据正文完整性鉴定。要保留的修改应先另存。若 Trash 报错且原目录还在，则保留并报错；若系统已移动但返回错误，会如实说明原位置已消失，停止自动新建，让用户检查回收站。

初始化中断后的 `preparing` 不会触发盲目补写。可认证且满足清点条件时可确认重置；无法认证的残片仍保留，不能以“修复演示”为由删除未知资料。

## 常见受阻情况

| 提示/情况                              | 安全的下一步                                                                               |
| -------------------------------------- | ------------------------------------------------------------------------------------------ |
| 最近目录缺失、已变化、磁盘离线         | 恢复挂载或手动重新选择确定的目录；应用不自动寻找                                           |
| 扫描不完整                             | 查看上限/权限/深度原因；必要时在同一明确根目录重新扫描或逐项处理已发现文件，勿把小计当总量 |
| 深查发现旁路文件、进程运行或未知       | 正常退出有关客户端并重新核实；不手删 WAL/SHM、不关闭保护强行继续                           |
| 深查超时、取消、未知结构或辅助进程异常 | 保留数据库，核对状态后重试；没有可用指标就不做可释放量推断                                 |
| 旧批次未认证                           | 保留整批文件，导入自己的原钥匙备份；钥匙导入不承诺跨路径自动恢复                           |
| 原路径已有同名文件                     | 先检查并妥善保存冲突内容；应用绝不覆盖                                                     |
| Linux Trash 不可用                     | 通过发行版/桌面正常配置原生工具与后端；隔离文件保留，不退回永久删除                        |
| 演示重置被未知内容阻止                 | 先人工移出或另存额外资料，再重试，不删除未知文件                                           |

## 验证范围与发布状态

本文按当前源码及分层测试证据编写，不宣称所有功能、全部平台或断电场景无误。

- 新增功能已有单元、真实诊断辅助进程、取消/超时/父进程退出、服务层安全与双主题 UI 定向验证。[双主题状态记录](app-data-regression/states.json)；最终整套回归以最后一次完整报告为准，不将迭代中的数量写成最终结论。
- 旧 `AgentVac` 基线已在真实 Linux 桌面以 sandbox 启用状态验证窗口/IPC、隔离恢复、偏好、目录对话框及标准 XDG Trash 往返，最后验证还原文件哈希。[旧基线原生证据](native-linux-baseline/README.md)
- 旧基线的成功不能替代新版本验收；新版本已额外完成 source/tar.gz 原生主流程、6 个目录/钥匙对话框、持久演示/偏好及标准 Trash 往返。当前实际运行的 Codex 进程被正确检测，深查及其取消/关窗需在没有 Codex 的授权环境复验。标准 `trash-cli` 还原并非图形 Restore；AppImage/FUSE 与图形回收站后端也仍需验收。[新版报告](native-linux-next/README.md)
- macOS / Windows 尚未完成本次 CI 和原生验收，Developer ID/公证与 Authenticode 签名未完成。私有 GitHub CI 的授权和构建附件不等于正式发布授权。
- 测试只操作合成夹具，不扫描实际用户 `.codex`。浏览器桥接 UI 与 Electron helper 测试各有覆盖边界，不冒充完整原生安装、权限及系统回收站测试。

本版不执行日志库清理、压缩、删除、模式转换或 Codex 升级；也不承诺内核级路径事务隔离、突然断电一致性或恶意并发安全。
